# 发布 NoNo

此技能被明确调用时才执行提交、标签和推送。仅修改版本规则或排查编译不等于调用发布。

## 标签合同

- 正式首版：`v3.8.1-xmod`；同一官方基础的新修复依次为 `v3.8.1-xmod.1`、`.2`，修订按整数排序。
- `deploy beta`／`deploy alpha`／`deploy rc`：使用 `v3.8.1-beta.1-xmod` 等渠道标签，各渠道编号独立。相同基础已经有 xmod 正式版时不再创建更早的预览版。
- 基础号来自官方标签对应的实际提交祖先。仅本地缓存了 `v3.8.3` 不证明 HEAD 已集成它；不得为绕过冲突从 3.8.1 擅升到 3.8.2。
- 历史无品牌版本继续可读取，不作为新标签输出。`xmod` 是正式发行品牌，不是预发布渠道。
- 旧标签不可重打或移动。同一源码补发复用旧标签的工作流仍须核对源码和镜像来源；新源码用新修订。

## 执行步骤

1. 检查当前改动，区分本轮实现与用户或其它任务的内容；只提交授权范围。
2. 确认本轮关联检查通过，不用旧测试结果证明新代码可发布。
3. 使用仓库 `.venv` 计算标签，正常命令会核验完整 Git 历史和实际官方来源，并同时考虑本地与发布远端标签：

   ```powershell
   .\.venv\Scripts\python.exe .agents/skills/deploy/scripts/next_tag.py release --remote origin
   .\.venv\Scripts\python.exe .agents/skills/deploy/scripts/next_tag.py beta --remote origin
   ```

   `--upstream-tag` 可明确期望基础号，但正常发布仍核对它与实际已集成最新官方版本一致。`--tag` 只供离线计算演练，不替代来源验证。网络或来源核验失败时停止，不能猜测版本。
4. 按用户与仓库的提交规范暂存、检查并提交。提交信息使用简体中文，类型遵循当前 AGENTS／会话规定；不得将不相关改动夹带进发布。
5. 在新提交上创建新的注释标签，检查对象与源码提交：

   ```powershell
   git tag -a <计算出的标签> -m <计算出的标签>
   git show --no-patch --decorate HEAD
   ```
6. 用户已明确要求发布或推送时，推送提交与新标签到发布远端；用户明确仅本地时停在本地标签。`git push` 成功后继续检查实际标签的 Actions 和完整便携附件。
7. 交付仍为 `NoNo-win32-portable.zip`。从不识别 xmod 的旧启动器首次升级，需要下载完整 ZIP、退出 NoNo 后解压覆盖；不能声称旧“检查更新”能发现它无法解析的新标签。

## 约束

- 不因标签后缀包含连字符就把正式 xmod 发布标成 prerelease。
- 官方来源、源码标签、镜像部署标签分别验证；不能向上游查询本项目的 xmod 标签。
- 不修改 `.venv` 或固定官方源码来临时通过编译。启动器和 Python 更新器适配必须登记来源与完整结果。
- 不覆盖历史标签，不未经要求推送，不把本地标签成功等同于 Release 已完成。
